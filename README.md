## 🚀 About Me

I'm a **backend engineer** who builds the parts of software that users never see but always depend on. I currently work on **large-scale backend infrastructure handling 100M+ (10 crore+) records**, where every query, index, and architectural decision has a real impact on performance.

At that scale, "it works" isn't enough. Systems need to be **fast, reliable, and ready to grow**. That's the kind of engineering I enjoy most: designing clean architecture, optimizing databases that hold massive amounts of data, building APIs that stay responsive under load, and shipping everything in consistent, containerized environments with **Docker**.

I like solving the hard backend problems: slow queries, bottlenecks, scaling limits, and messy legacy systems that need to be turned into something clean and maintainable.

## ⚙️ What I Work On

- 🏗️ **System Architecture:** Designing backend systems that stay stable and maintainable as data and traffic grow
- 🗄️ **Large-Scale Data:** Managing and optimizing databases with **100M+ records** through smart indexing, query tuning, and efficient schema design
- ⚡ **Performance Engineering:** Finding bottlenecks and fixing them with caching, query optimization, and background job processing
- 🔌 **API Development:** Building secure, well-structured REST APIs with **Laravel** that other teams and apps can rely on
- 🐳 **Containerization:** Packaging and deploying services with **Docker** for consistent environments from development to production
- 🔒 **Reliability:** Writing backend code that handles failures gracefully, because at scale, edge cases happen every day

<br>

## 🧠 How I Approach Backend Engineering

| Principle | What it means to me |
|---|---|
| **Design before code** | Think through data flow, architecture, and scale before writing the first line |
| **Measure, then optimize** | Use real data and profiling to find bottlenecks instead of guessing |
| **Simple beats clever** | Clean, readable code is easier to maintain, debug, and scale |
| **Build for tomorrow's load** | Today's 100M records will be tomorrow's 500M, so plan for growth |
